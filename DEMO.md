# DEMO — owned by the Demo Owner, written at T+10, not T+120

Writing the demo at the end is how teams with working code still lose. Write it
now, then build only what it needs.

---

## The golden path — exactly three steps

Everything the team builds for the next 80 minutes serves these three clicks.
If a proposed feature is not one of these steps, the answer is no.

1. **...**
   - Say: "..."
   - Click: ...
   - They should notice: ...

2. **...**
   - Say: "..."
   - Click: ...
   - They should notice: ...

3. **...**
   - Say: "..."
   - Click: ...
   - They should notice: ...

## Opening line (15 seconds, memorised)

> Today, [who] has to [painful thing], which takes [time]. We built [name], which
> does it in [much less time]. Here it is working.

No agenda slide. No architecture diagram. No team introductions. Open on the
hero screen with real data already loaded and start clicking.

## Closing line (10 seconds)

> That is running live at [URL] right now, built in two and a half hours with
> GitHub Copilot doing [the specific thing]. Happy to take questions.

## Pre-demo checklist — run this at T+105 and again at T+130

- [ ] Live URL loads from a **cold** browser profile (no cache, not logged in)
- [ ] Loads on a **phone** on mobile data, not just the office wifi
- [ ] Browser zoom at 100%, bookmarks bar hidden, notifications silenced
- [ ] Demo tab is the **only** tab open; no localhost tab anywhere
- [ ] Seed data looks realistic on the hero screen — no "Item 1" anywhere
- [ ] Light mode (projectors mangle dark mode)
- [ ] Every click in the three steps works, twice in a row
- [ ] **Backup video recorded and downloaded locally** (not streaming from cloud)
- [ ] Someone other than the Demo Owner has run the path once

## If something breaks live

1. Do not debug on stage. Do not open devtools.
2. Say: "That is the live build — let me show you the recorded run."
3. Play the backup video. Keep talking over it.
4. Total recovery time should be under 10 seconds. Rehearse this too.
